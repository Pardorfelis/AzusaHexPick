# 结构与状态约定

## 启动器与交付结构

v0.7.1 在现有应用外增加 Inno 安装向导与独立静态官网。安装向导校验专用目录，委托 Velopack 安装并选择桌面快捷方式，不另建卸载登记。安装和便携版共用当前用户数据目录；更新仍由 Velopack 完成。

~~~mermaid
flowchart LR
  Site[香港 COS 静态官网] --> Download[安装版或便携版]
  Download --> Launcher[WPF 启动器]
  Launcher --> Web[本机控制台]
  Launcher --> Desktop[不激活的桌面副屏]
  Web --> Network[物理网卡与默认路由推荐]
  Network --> Phone[单一配对只读地址]
  Launcher --> Primary[COS 稳定更新清单]
  Launcher --> Fallback[GitHub 正式 Release 备用]
  Local[维护者本地官网配置] --> Build[静态白名单构建]
  Guide[同一份离线教程] --> Build
  Build --> Site
~~~

官网源码位于 site，构建仅复制明确的素材、共享教程、已验证下载包和更新包。网站不包含本机控制路由、配对令牌或密钥；背景切换只在维护者本地配置并重新构建。默认背景作者姓名不显示在界面。

更新主地址配置在 delivery.json 的 updateBaseUrl，介绍地址为 introductionUrl。主清单不可访问时可检查 GitHub 备用源，下载期间固定来源与目标版本；网络下载失败后允许下次检查优先备用源，取消、磁盘或哈希错误不触发换源。正式构建核对包内配置和 SHA-256，部署包先于清单，阻止覆盖同名不同内容包及版本回退。域名尚未准备时只生成本地预览，不发布占位更新地址。

src/network.mjs 用 Windows 物理网卡、IPv4、默认路由和接口优先级推荐一个手机地址，排除 VPN、VMware 等虚拟网络。手机页显示推荐链接，其他真实网络与高级热点地址折叠。健康检查使用异步合并探测及缓存，刷新地址不改轮次，服务退出中止探测。配对、只读和本机控制权限不变。

v0.7.0 增加 Windows x64 自包含 WPF 启动器，使用 .NET 10 和 Velopack。启动器负责本项目进程、托盘、当前用户密钥、设置导入及更新；Node 服务仍负责计票，Tkinter 副屏仍消费同一快照。网页继续使用原生 HTML、CSS 和 JavaScript，没有新增前端框架。

~~~mermaid
flowchart LR
  U[梓有妙选.exe] --> P[自带 Node 服务]
  U --> T[自带 Tkinter 副屏]
  P --> W[本机控制台与只读页]
  W --> A[本机应用管理接口]
  A --> B[临时回环桥接]
  B --> U
  U --> D[Windows 用户数据目录]
  U --> V[Velopack 更新]
  V --> G[GitHub 正式版本]
  W --> Q[主动打开腾讯问卷]
~~~

发布目录保留 Velopack 所需结构，日常入口为「梓有妙选.exe」。app 中包含服务、网页、目录及脱敏回放；runtime 中提供 Node 和打包后的桌面副屏。没有开发环境的用户无需另装 SDK。源码开发模式及旧脚本仍可独立使用，不具备已安装更新器时才有的应用内更新能力。

Program.cs 先运行 Velopack 启动处理，并显式关闭启动时自动应用更新。启动器使用互斥量限制单实例，第二次启动通过当前用户命名管道唤回已有窗口。ProcessManager.cs 只管理自己启动的 Node 和桌面进程，退出时释放本项目连接及快捷键，不扫描或终止无关程序。

LocalBridge.cs 在随机回环端口建立临时管理接口，使用随机秘密校验、恒定时间比较、Host 检查并拒绝 Origin。地址和秘密仅通过子进程环境传递。Node 的 src/application.mjs 只返回白名单状态，不将桥接秘密或模型密钥提供给网页。GET /api/application 与 /api/application/diagnostics 仅限本机；应用管理 POST 继续检查本机、Host、Origin、JSON 类型及 X-Panel-Control。配对手机不能执行这些操作。

public/application.js 处理常驻应用按钮、首次上手提示、更新和反馈，不计算票数。腾讯问卷仅在使用者主动打开时加载，CSP 的 frame-src 只加入 https://wj.qq.com，保留外部页面备用入口。诊断采用版本、模式、连接、计数和 AI 状态白名单，不包含密钥、完整弹幕、昵称、真实 UID、配对令牌或私人路径，也不自动提交给第三方。

## 用户数据与迁移

启动器默认使用 `%LocalAppData%\AzusaHexPick\UserData`。AZUSA_USER_DATA 仅用于显式隔离测试或部署数据目录，启动器向服务和副屏传递同一目录。源码直接运行没有此变量时，保留原项目内的数据位置。

| 文件或目录 | 用途 |
| --- | --- |
| launcher.json | 启动器偏好、手机模式及反馈链接 |
| deepseek.key | 使用 Windows DPAPI CurrentUser 保存的模型密钥 |
| app-settings.json | 装备与海克斯 AI 开关、模型选择 |
| appearance.json 与 backgrounds | 三处外观、图库索引和导入图片 |
| song-blacklist.json | 持久化长期黑名单 |
| runtime/desktop-display-5178.json | 桌面尺寸和倍率 |
| backups | 导入或更新前的配置备份 |

密钥只有启动器在当前 Windows 用户下解密后注入服务进程，不写入网页响应、诊断、日志、仓库或发布包。新交付配置在有密钥时默认开启装备 AI，关闭海克斯 AI，使用 Flash；之后恢复保存的用户偏好。开发模式继续默认关闭 AI。本场灰名单和当前轮次仍只在服务内存中，重启后清空。

设置导入只允许旧版外观、黑名单、显示配置及被索引引用的背景文件。先检查大小、格式、哈希、符号链接和目标是否存在，再备份并复制；不改源文件，不覆盖新目录中的已有个人配置。复制失败撤销本次新增文件，保留备份。旧 `.env.local` 不迁移，密钥由使用者在启动器重新填写。

## 更新状态与保护

v0.7.1 的 UpdatePolicy.cs 优先读取正式官网的 COS 稳定更新清单，GitHub Releases 为网络检查的备用源；v0.7.0 仍从 GitHub 获取这次过渡版。客户端不携带 GitHub 访问令牌，排除测试、草稿与预发布版本。启动和手动检查都异步进行，只有用户点击更新才下载、应用和重启。测试源通过专用编译条件启用，不进入正式客户端。

应用更新前、下载后和停止服务前分别确认收集状态。Node 的 prepare-update 会锁住新轮及相关控制操作，cancel-update 可撤销准备状态，避免下载期间又开始的新轮被中途重启。下载结果先由 Velopack 校验，磁盘空间检查和个人设置备份通过后才关闭服务；长期数据目录不在程序替换范围内。

完整包缓存按固定更新目标的远端大小与 SHA-256 复核。差量链先检查基础包，由 Velopack 核验各差量包；重建后的 ZIP 另核对 package-manifest.json、完整文件集合、逐文件大小与哈希及核心文件。重建压缩包的封装字节不必与远端完整 ZIP 相同，不能用后者的容器哈希误拒绝有效差量。受检重建缓存的实际大小、哈希和固定目标身份使用当前 Windows 用户的 DPAPI 凭据保护，重新启动后仍复核；未知缓存、凭据被改动、内容损坏或目标变化均拒绝复用。损坏包只清理本项目已确认的缓存文件，保留当前程序与个人设置，再允许重新下载。

完整更新包为回退路径，有上一版基础包时可生成差量包。网络、校验、取消或空间检查失败会明确显示状态，保留当前程序和设置。更新说明、完整包、差量包及渠道清单必须随 GitHub 正式 Release 发布，仅推送源码不会产生客户端可用更新。发布步骤见 [发布约定](releasing.md)。

## 计票与显示

~~~mermaid
flowchart LR
  A[游客直播源] --> E[PanelEngine]
  B[脱敏回放源] --> E
  E --> C[本地装备归并]
  E --> K[本地海克斯分层识别]
  E --> S[本地点歌识别与次数]
  S --> E
  SG[本场灰名单] --> S
  SB[本机限期黑名单] --> S
  K --> E
  K --> L[少量未决数字表达]
  L --> D
  C --> D[可选 DeepSeek 归并]
  D --> E
  E --> F[本机 HTTP 状态与事件]
  F --> G[操作台与副屏网页]
  F --> H[Windows 只读桌面窗]
  F --> I[配对手机页]
  J[全局快捷键助手] --> F
~~~

src/engine.mjs 是唯一计票状态来源，两个显示载体不会重新计票。回放和直播消息都统一为消息编号、文本、匿名来源、接收时间及源代次。

轮次状态为未开始、收集中、暂停和已锁定。断连停止收集；恢复连接开新轮。消息去重缓存跨轮保留且有界，回放跳转生成新的播放编号以允许重复试验。

装备归并不承担游戏推荐。它只整理观众表达中的首选、反对、先后、条件和备选。模型输出必须经过本地校验；状态层再次检查来源、轮次、版本和时限。

普通网页适合验证操作和扫读；Windows Canvas 负责不激活、置顶及原生快捷键，消费同一快照。修改接口字段时需要同时核查两个显示载体。

默认服务绑定 127.0.0.1。局域网模式绑定 IPv4 接口，只读页面要求随机配对令牌；控制、回放目录、健康与配置接口仅本机可访问。HTTP 控制还检查主机、来源、自定义请求头及 JSON 类型，静态文件使用白名单。

src/hex.mjs 只做受限文本识别，不计算票数。引擎保存精确指令、重复数字、明确短句及 AI 的累计计入数。AI 解释只能确认文本中已有的单个候选。明确反对更新匿名修订、撤回匿名支持，消息历史不倒扣；来源、轮次、修订和截止时间校验仍由引擎统一执行。

共享快照包含计数、状态和达到重复阈值的短装备候选词，不包含完整弹幕原文或匿名标识。本机 GET /api/hex-audit 和 GET /api/equipment-audit 各提供最多 20 条相关原文样本，手机令牌不授权这两个接口。样本随轮次清空，不建立持久直播原文日志。装备与海克斯 AI 开关独立，海克斯在末段且明确本地建议不足 20 条时才调用；阈值用于调用策略，不表示置信度。

海克斯的 d、12d、13d、23d 是完整动作，与原六项同级计票，不拆成单项票。陌生装备词只从有界未决记录提取和归并，达到三次提及后单独展示，不进入确定推荐。消息原文、判断与短候选词各有独立边界，模型不能通过返回词面直接添加票数。

装备标准名与核实的昵称属于运行数据；名称资料的来源和同版本精简元数据只用于核查。检索返回每条文本实际提及的标准名，不以全部目录喂给模型。响应先通过全目录校验，再检查该条候选子集，跨样本借用装备名会整批拒绝。含待确认陌生词的表达暂不发起请求，避免已知部分被错误提升为首选。

AI 从最多 2000 条有界记录中选取新鲜候选，过滤过期和不可靠名称后合并相同原文，每批最多三种。缓存以模型、模式、完整原文及海克斯候选为键，最多 64 项，按轮清空；同文消息各自保留回填票据。每条票据仍经过来源、轮次、匿名修订和时限检查。装备请求按实际首次请求时间及整轮四分之一间隔分散，四次请求、轮费用和会话费用三类限制分别展示。

共享 equipment.unknown 只含短原词和本轮条数／匿名标识数。equipmentDiagnostics 记录本地与 AI 分类数量、忽略原因和待确认阈值。本机 equipment-audit 提供最多 20 条原文及分类依据，前端切换模式或轮次后丢弃旧接口结果。

服务不保存 API 密钥至报告，不记录直播昵称或真实 UID。原始 XML 只读，导入数据中的消息标识与匿名来源使用重新加盐的哈希；样本原文保留用于语义验证。

点歌模式强制按消息计次，不更新匿名改票或 AI 队列。src/songs.mjs 负责目录与表达识别，src/song-lists.mjs 管理本场灰名单及原子写入的持久黑名单；引擎仍是计数的唯一来源。名单过滤发生在接收时，也会从当前展示中隐藏已计入歌曲。周期快照主动清理过期黑名单，不依赖新弹幕触发。

共享 songs.items 与 songs.singles 仅包含歌曲名称、键、次数和是否命中目录。完整黑名单、灰名单和识别原文仅在本机接口读取。灰名单添加校验当前轮次和可见歌曲，移除校验当前场次，防止旧界面误操作新轮或新场。

## 网页视觉与资源

v0.6.0 新增 src/appearance.mjs，独立管理外观配置、图库索引及递增版本。public/themes.json 供网页与桌面共享款式。public/appearance.js 负责主题、图库及背景动效，app.js 保持计票展示与操作；外观变化不调用计票控制。

快照的 appearance 包含版本、三处设置与当前背景信息，图库索引仅由本机 GET /api/appearance 返回。POST /api/appearance、POST /api/backgrounds/import、edit 和 delete 沿用本机、Host、Origin 及 X-Panel-Control 校验。上传采用独立二进制请求，限制 10 MB 并校验格式结构及尺寸，原 JSON 控制请求仍为 64 KB。自定义图片只允许固定哈希路径，局域网读取校验配对令牌。

设置及图库索引原子保存于用户数据目录的 appearance.json；源码开发模式仍使用 data/appearance.json。写操作串行执行，失败不替换内存状态。图片按内容去重，删除先保存引用回退再清理文件。桌面仅在主题改变时更新调色盘与材质，不改变图片缓存、字号及命中坐标。视差只响应指针事件，后台或停用时取消待处理帧。

v0.5.0 的网页仍由 public/index.html、style.css 和 app.js 组成，不增加框架、构建步骤或运行时依赖。所有控件沿用原有编号和事件入口；新增的显示状态仅决定空状态立绘、锁定反馈和歌曲首次入列动画，不参与识别与计票。

public/assets 中五幅网页图片及 Manrope 字体通过 server.mjs 的精确路径白名单提供。桌面专用 logo 不开放 HTTP 路由。字体、图片可被只读页加载，名单管理、控制与识别原文接口仍仅限本机。没有开放整个资源目录，也不提供任意路径读取。源码与便携包附素材来源及字体许可，打包明确列出六幅图片、字体及许可文件。

桌面助手仍使用 Tkinter 与原有 Win32 不激活窗口。两张 PNG 在启动及显示倍率变化时读取并缓存，裁切与整数采样仅影响显示，不改变原文件；普通轮询和尺寸拖拽不会重新读取图片。缺失或损坏的素材不会阻断计票显示。不增加图像运行依赖，轮询、后台队列、快捷键、名单请求与轮次校验保持原有入口。

v0.5.1 将物理窗口尺寸与逻辑绘制尺寸分开，由显示倍率统一转换绘图坐标、字体度量和点击坐标。窗口高度决定点歌列表可见行数，底部统计、倍率按钮和 logo 随高度移动。边缘拖拽通过 Win32 的不激活尺寸调整更新窗口，保留原有不激活样式；不改变计票服务。尺寸及倍率经有限值、分档、最小布局和屏幕工作区校验后写入 .runtime 中的端口专属文件，采用临时文件替换，损坏或过大的配置回退至默认。

v0.7.0 将交付包的尺寸文件移到用户数据目录的 runtime，原缩放与命中逻辑保留。桌面标题右侧电源图标单击弹出确认窗，取消不发出退出请求，确认后使用现有后台控制队列发送 exit-all；叉号继续仅关闭桌面窗。确认弹窗按当前主题显示，常规结果窗口保持原有不激活样式。
