# 自行更换官网背景教程

这份教程用于更换 `https://azusa510.top/` 的背景。整个过程是：放入图片 → 修改配置 → 本地预览 → 上传网站。只改背景不需要发布新的软件版本，梓神也不需要更新或重装软件。

官网与网页控制台的背景各自独立。官网没有对访客开放换背景的按钮，只有我在本地修改配置并上传后，访客才会看到新背景。

## 一、准备一张图片

- 支持静态 JPG、PNG、WebP，单张不超过 10 MB。
- 优先选横向图片，例如 1920 × 1080。手机屏幕较窄，左右两侧会被裁切，所以重要内容尽量不要紧贴边缘。
- 文件名建议使用英文字母、数字和短横线，例如 `my-background.png`。只使用自己可以公开展示的图片。

当前默认图片是 AI 生成的「月夜荷塘」，保存在 `site/backgrounds/azusa-moonlit-lotus.png`。

打开项目文件夹，依次进入 `site` → `backgrounds`。新建一个名为 `local` 的文件夹，把准备好的图片复制进去。以下步骤以 `site/backgrounds/local/my-background.png` 为例。

`local` 文件夹属于本地图库，不会随 Git 提交或源码包发布；构建网站时只会取出选中的一张图片。

## 二、指定要使用的背景

进入项目的 `site` 文件夹，找到 `config.local.json`。

**如果它已经存在，先复制一份备份，再修改里面的背景设置，不要直接覆盖其他配置。** 如果不存在，用记事本新建文件，粘贴下面的内容。

```json
{
  "background": "my-background",
  "backgrounds": [
    {
      "id": "my-background",
      "file": "backgrounds/local/my-background.png",
      "name": "我的背景",
      "position": "center"
    },
    {
      "id": "none",
      "file": "",
      "name": "无背景",
      "position": "center"
    }
  ],
  "parallax": true
}
```

保存时选择「另存为」，文件名填写 `config.local.json`，保存类型选择「所有文件」，编码选择 UTF-8，保存到 `site` 文件夹。请在资源管理器中开启「显示文件扩展名」，确认文件没有变成 `config.local.json.txt`。

这些字段可以这样理解。

| 字段 | 作用 | 修改方法 |
| --- | --- | --- |
| `background` | 当前选中的背景 | 必须与下面某一项的 `id` 完全一致 |
| `id` | 图片的识别名称 | 自己起一个不重复的英文名称 |
| `file` | 图片的位置 | 从 `site` 文件夹开始填写，使用 `/` 分隔文件夹 |
| `name` | 图库中的名称 | 可以填写中文，不会作为官网标题展示 |
| `position` | 图片的显示中心 | 通常使用 `center`，也可以试试 `center 42%` |
| `parallax` | 是否启用鼠标视差 | `true` 开启，`false` 关闭 |

图片叫别的名字时，修改 `file` 最后面的文件名即可。例如图片是 `lotus.jpg`，就填写 `backgrounds/local/lotus.jpg`。

**JSON 使用英文双引号和英文逗号。** 不要把示例中的标点替换为中文标点，也不要在最后一项后面多加逗号。`true` 和 `false` 不需要引号。

`config.local.json` 优先于默认配置，未填写的域名等设置会沿用 `config.json`。但 `backgrounds` 会替换整个默认列表；如果想在本地保留多张图片，就在这个列表里添加更多项目，再修改 `background` 选择其中一张。不要为了换背景改动域名、更新地址或问卷地址。

## 三、重新构建并预览

这一步在**项目源码文件夹**中操作，不是在解压后的软件安装目录中操作。项目根目录能看到 `package.json`、`scripts`、`site` 等文件。

在这个文件夹的空白处右键，选择「在终端中打开」或「在此处打开 PowerShell 窗口」，然后依次执行下面的命令。

```powershell
node scripts/build-site.mjs --release
```

构建成功后会显示包含 `"formal":true` 的结果。它会重新生成 `dist/site`，同时核查已有的正式软件下载文件，不会重新编译软件。

第一次预览时，继续执行：

```powershell
node scripts/preview-site.mjs
```

浏览器打开 <http://127.0.0.1:5281/>。检查新背景是否出现、文字是否清楚，再把浏览器窗口缩窄，看看手机尺寸下的裁切。网页仍会保留原有的浅色遮罩和轻微鼠标视差。

如果之前的预览服务还在运行，构建后直接刷新网页即可，不需要再启动一次。提示端口被占用时，也先尝试打开上面的预览地址。结束预览服务可以在它所在的终端按 `Ctrl + C`。

终端正在运行预览服务时，可以另外打开一个位于项目根目录的 PowerShell 窗口，执行下一步的上传命令。

> 如果提示正式安装包、演示视频或运行环境缺失，说明当前源码目录还没有准备齐正式网站所需文件。请先恢复本项目已有的 `dist/releases`、`dist/delivery` 和构建环境，再继续。不要手动改 `dist/site` 来绕过检查，也不要为了换背景覆盖已发布的软件包。

## 四、上传到官网

确认本地预览没有问题后，在项目根目录执行：

```powershell
& .\scripts\publish-site.ps1 -Publish
```

根据终端提示，在自己的电脑上输入专用部署子账号的 `SecretId` 和 `SecretKey`。输入内容不会回显，脚本只在本次上传时使用，完成后恢复进程环境；不要把密钥写进配置文件、聊天或截图。

等待脚本报告成功。它会上传并核验网站文件，已经发布且内容一致的软件包会先核验后跳过上传，因此等待时间也包含核验时间。看到仍在上传或校验时，不要提前关闭窗口。

上传结束后，打开 <https://azusa510.top/>，按 `Ctrl + F5` 刷新，确认看到新背景。构建会根据图片内容生成新的文件名，一般不需要手动清除 COS 缓存。

只执行构建或预览，线上网站不会改变；必须上传成功才会生效。只运行 `publish-site.ps1` 而不加 `-Publish` 时，也只是本地检查，不会上传。

## 五、调整位置、关闭背景或恢复默认

**调整裁切位置。** 在 `config.local.json` 中把 `position` 改为 `center 42%` 等值，然后重新构建、预览和上传。图片仍以铺满屏幕的方式显示，不会被拉伸变形。

**关闭鼠标视差。** 将 `parallax` 改为 `false`，再执行构建与上传。访客也可以通过官网的「暂停动效」按钮暂停背景运动。

**暂时不用背景。** 保留示例中的 `none` 项，将 `background` 改为 `none`，再构建与上传。

**恢复项目默认背景。** 将 `site/config.local.json` 改名为 `config.local.json.bak`，再构建、预览和上传。当前默认图会恢复为「月夜荷塘」。图片原文件可以继续留在本地图库中。

## 常见问题

| 提示或现象 | 处理方法 |
| --- | --- |
| 找不到图片文件 | 核对 `file`、图片实际名称及扩展名；路径从 `site` 文件夹开始计算 |
| 选中的背景不在本地图库中 | 检查 `background` 是否与某一项 `id` 完全一致 |
| JSON 解析失败 | 检查英文引号、逗号、括号，以及是否多写了最后一个逗号 |
| 图片超过大小限制 | 在图片工具中缩小尺寸或另存为 JPG／WebP，将文件控制在 10 MB 以内 |
| 本地已经换图，官网还是旧图 | 确认使用 `--release` 构建，并完成带 `-Publish` 的上传，再强制刷新网页 |
| 修改默认配置后没有变化 | 检查是否存在 `site/config.local.json`，它会覆盖默认设置 |
| 上传失败 | 按错误提示处理后重试；不要发送密钥或截图包含密钥的窗口 |

以后通常只需要做三件事：把新图片放进本地图库，修改 `config.local.json`，然后构建并上传。官网访客无需做任何操作。
